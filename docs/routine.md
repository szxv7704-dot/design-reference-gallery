# 루틴 절차: 참고 변주 채우기 (꺼 둠)

> 이 루틴은 2026-11-13에 꺼 두었다. 갤러리가 "참고용 장표 모음"으로 정리된 뒤의 구조(분위기별 덱 · `catalog.md` · `light/`)와 맞지 않는 부분이 있으니, 다시 켜기 전에 이 문서부터 고친다.

평일 새벽에 도는 루틴이 이 문서를 그대로 따른다. 고칠 일이 생기면 루틴 프롬프트가 아니라 이 문서를 고친다.
사용자는 자는 중이라 질문할 수 없다. 스스로 판단해 끝까지 하고, 막히면 아무것도 올리지 않고 이유를 보고한다.

## 무엇을 하나
참고 장표가 가장 적은 **기본 장표** 하나를 골라, 그 기본 장표의 **변주 한 장**을 만들어 `main`에 올린다.
변주는 첫 화면의 그 기본 장표 카드 아래 '참고할 변주'에 나온다. AI가 덱을 만들 때 "이렇게도 풀 수 있다"는 생각거리가 된다.

- **변주란**: 같은 내용의 모양(기본 장표)을 **다른 짜임**으로 푼 것. 키트의 견본과 겉모습(색 · 글꼴)은 같고 배치 · 강조 방식 하나가 다르다.
  예) 항목 → 번호 줄 대신 2 × 2 칸 / 한 문장 → 문장 옆에 받치는 숫자 하나 / 질문 → 보기 대신 양쪽 갈래(예 · 아니오).
- **한 장에 기본 장표 하나.** 도식을 둘 넣지 않는다. 키트 견본보다 정보를 더 넣지 않는다.

## 순서

```
git fetch origin && git checkout main && git pull --ff-only origin main
pip install -q fonttools brotli            # 없을 때만
python3 scripts/variant.py next            # 번호 · 채울 기본 장표 · 계열
python3 scripts/variant.py new 번호 계열 기본장표id
#  → src/번호/page.html 을 변주로 고친다, data/rounds.json 에 항목을 넣는다
python3 scripts/variant.py add 번호        # 빌드 · 썸네일 · 검사 · 판정표 · 첫 화면
git add -A && git commit -m "레퍼런스 #번호 반영: 기본장표 이름 변주" && git push origin main
```

1. **하루 한 장.** `data/rounds.json`에 오늘(`TZ=Asia/Seoul date +%F`) 날짜 항목이 이미 있으면 아무것도 하지 않고 끝낸다.
2. `variant.py next`가 알려 준 번호 · 기본 장표 · 계열을 쓴다(실행 메시지에 따로 적혀 있으면 그것을 따른다).
3. `variant.py new`가 만든 `src/번호/page.html`에는 그 기본 장표의 키트 견본 장이 들어 있다. 먼저 `docs/patterns.md`에서 그 기본 장표의 내용 조건을 읽고, 첫 화면에서 같은 기본 장표의 기존 변주(`data/triage.json` · `data/rounds.json`)를 보아 겹치지 않는 짜임을 정한다.
4. 견본 장을 **변주로 고친다.**
   - 새 모양은 `<style>`의 '변주 부품' 줄 아래에 새 클래스로 쓴다. 색 · 글꼴 · 모서리 · 그림자는 **토큰 변수(`--ds-*`)만** 쓴다(헥스 직접 금지) — 그래야 여덟 계열 어디에나 옮겨진다.
   - 키트 클래스(`.s-body` · `.kicker` · `.title` · `.fill` · `.src` · `.page-no` · `.is-key`)는 그대로 쓴다. 키트 CSS 파일(`kit/`)은 고치지 않는다.
   - 내용은 교육청 업무의 **가상 예시**로 새로 쓴다(기관은 "○○교육청", 수치는 그럴듯한 가상값, 출처 줄에 "가상 예시"). 견본의 문구를 남기지 않는다.
   - 장은 1장. 같은 변주를 항목 수만 달리해 한 장 더 보여 주고 싶으면 2장까지.
5. `data/rounds.json` 끝에 항목을 넣는다(아래 필드를 모두).
   ```json
   {"no": 122, "date": "2026-11-16", "type": "변주", "role": "본문", "use": "발표 덱",
    "title": "레퍼런스 #122 두 칸 두 줄 항목", "topic": "늘봄학교 운영 원칙 네 가지",
    "summary": "무엇이 견본과 다른지 한두 문장", "takeaway": "가져갈 장치 한 줄(60자 안)",
    "pattern": "points", "family": "B", "motion": "정지", "domain": "돌봄·유아",
    "file": "refs/122.html", "thumb": "thumbs/122.jpg"}
   ```
   - `pattern`은 기본 장표 id(`docs/patterns.md` 3), `family`는 만든 계열, `motion`은 `data-step`을 썼으면 "모션" 아니면 "정지".
   - `domain`은 학생·교육과정 / 돌봄·유아 / 특수교육 / 업무·행정 / 시설·안전 / 지역·문화 중 하나.
6. `variant.py add 번호`가 "통과"를 내야 한다. 실패하면 `check/report.json`을 보고 고쳐 다시 돌린다(넘침이면 문장을 줄이거나 항목을 줄인다. 글자를 22px 아래로 줄이지 않는다). 두 번 고쳐도 안 되면 그 회차의 파일(`src/번호` · `refs/번호.html` · `thumbs/번호.jpg` · rounds.json 항목)을 모두 지우고 올리지 않는다.
7. 썸네일(`thumbs/번호.jpg`)을 직접 열어 본다. 아래 '스스로 보기'에 하나라도 걸리면 고친다.
8. 커밋하고 `main`에 올린다. 올리기 전에 `git pull --ff-only`로 다시 맞춘다. 거부되면 강제로 밀지 않고 보고한다.

## 스스로 보기 (모두 "예"일 때만 올린다)
1. 키트 견본과 **짜임이 실제로 다른가**(색만 바꾼 것이 아닌가)?
2. 한 장에 기본 장표가 하나인가? 견본보다 빽빽하지 않은가?
3. 제목이 결론 한 문장이고, 강조색이 한 곳인가?
4. 변주 부품이 토큰 변수만 쓰는가(`grep -n '#[0-9A-Fa-f]\{3,6\}' src/번호/page.html` 에 변주 부품 줄이 안 걸리는가)?
5. 코드로 그린 그림(사물 · 인물 · 풍경 · 지도)이 없는가? 제작 기준(`docs/criteria.md` 6)에 걸리는 것이 없는가?
6. 견본의 예시 문구가 남아 있지 않은가? 깨진 한글 · 빈칸이 없는가?

## 하지 않는 것
- `kit/` · `scripts/` · `docs/` · 기존 `refs/` · `src/flows/`를 고치지 않는다(`docs/triage.md` · `index.html` · `data/triage.json`은 `variant.py add`가 다시 만든 것만 커밋한다).
- 새 기본 장표 · 새 계열 · 새 예시 덱을 만들지 않는다. 필요해 보이면 보고에만 적는다.
- 아티팩트를 게시하지 않는다. 다른 저장소를 건드리지 않는다. PR을 만들지 않는다.
