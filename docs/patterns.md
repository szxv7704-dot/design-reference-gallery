# 기본 장표 틀

이 갤러리의 분류 기준이다. 장표를 "어떤 행사에 쓰나"가 아니라 **"내용이 어떤 모양인가"**로 나눈다.
기존 장표 판정은 [`triage.md`](triage.md), 그림 · 피할 것 같은 제작 규칙은 [`criteria.md`](criteria.md).

표의 원본은 `data/patterns.json` · `data/flows.json`이다. 고칠 때는 그 파일을 고치고 이 문서의 표도 맞춘다.
내용 조건의 숫자는 여덟 계열 예시 덱이 1920 × 1080 안에 들어가는 것을 `scripts/check.js`로 확인한 범위다.

## 1. 이 갤러리를 쓰는 방식

1. 사용자가 채팅 AI(Claude · ChatGPT)에게 **이 갤러리 주소와 자기 한글 문서**(계획안 · 연수 강의안 · 성과 보고 등)를 준다.
2. AI는 문서를 읽고, 여기 있는 디자인을 참고 · 재료로 삼아 **16:9 발표 덱 HTML**을 만든다.

그래서 갤러리의 첫 번째 독자는 AI다. 여기서 세 가지가 따라 나온다.

- 분류는 AI가 하는 일의 순서와 같아야 한다: 문단을 읽는다 → 그 문단의 모양을 정한다 → 그 모양의 장표를 고른다.
- AI가 읽는 면은 스크립트 없이 글로 읽혀야 하고, 한 장만 읽어도 덱을 만들 수 있어야 한다. 첫 화면(`index.html`)은 내용이 모두 HTML 안에 들어 있고, 같은 내용이 `guide.md`에 글로 있다.
- 자료는 두 가지로 나뉜다.
  - **재료**: AI가 그대로 가져다 조립하는 코드. 한 벌의 규격(덱 키트)으로 만든 부품만 해당한다.
  - **참고**: "이렇게도 풀 수 있다"는 생각거리. 기존 레퍼런스 장표가 여기에 해당한다. 썸네일과 요점만 넘기고 코드는 넘기지 않는다.

## 2. 세 층

| 층 | 무엇 | 정하는 것 | 원본 |
|---|---|---|---|
| 1. 기본 장표 | 내용의 모양 23가지 | 한 장의 짜임 | `data/patterns.json` · 부품은 `kit/parts.css`와 계열 CSS |
| 2. 흐름 | 기본 장표를 순서대로 엮은 것 | 덱의 순서 | `data/flows.json` · 예시 덱은 `src/flows/` |
| 3. 분위기 | 색 · 글꼴 · 상징 부품(A~H 키트) | 덱의 겉모습 | `kit/{계열}.css` · `kit/{계열}.design.md` |

세 층은 서로 독립이다. 어떤 흐름이든 어떤 분위기로든 나오고, 기본 장표는 모든 분위기에 다 있다.
행사마다 새 장표 유형을 만들지 않는다. 행사에 따라 달라지는 것은 순서와 자리 이름뿐이다.

## 3. 기본 장표 23가지

| 묶음 | 기본 장표 | `pattern` | 문서에서 이런 내용이면 | 내용 조건 | 넘치면 | 부품 |
|---|---|---|---|---|---|---|
| 뼈대 | 표지 | `cover` | 문서 제목 · 기관 · 날짜 | 제목 2줄 이하, 부제 1줄 | 부제를 뺀다 | `.cover` |
| 뼈대 | 목차 | `toc` | 문서의 큰 번호(Ⅰ · Ⅱ · Ⅲ), 차시 순서 | 3~5줄 | 큰 묶음으로 합친다 | `.toc + .toc-list` |
| 뼈대 | 간지 | `divider` | 큰 번호가 바뀌는 자리 | 번호 + 이름 + 한 줄 | — | `.divider` |
| 뼈대 | 맺음 | `closing` | 문의처 · 담당 · 다음 차시 예고 | 두 줄 문장 + 연락처 한 줄 | — | `.close` |
| 글 | 한 문장 | `statement` | 목적 · 비전 · 결론처럼 한 문장이 전부인 곳 | 40자 이하 한 문장 + 받치는 말 1줄 | 받치는 말을 다음 장으로 | `.say` — 이 장만 .title 없이 .kicker 아래에 둔다 |
| 글 | 항목 | `points` | 개조식(□ · ○ · -) 항목 3~5개, 학습 목표, 기대 효과 | 3~5개, 이름 + 설명 1~2줄(5개면 1줄) | 6개부터 두 장, 또는 묶음·분류로 | `.points` — 네 칸으로 한눈에 보일 때는 .brief(목적 · 대상 · 기간 · 규모) |
| 글 | 용어 정의 | `define` | "○○란", 용어 풀이, 개념 설명 | 용어 1개 + 뜻 한 문장 + 예 1~2개 | 용어마다 한 장 | `.define` |
| 글 | 인용 | `quote` | 참여자 말 · 설문 서술 답 · 법령 조문 | 1~3개, 각 60자 이하, 말한 사람 | 가장 강한 것 하나만 | `.quote` |
| 관계 | 순서·단계 | `steps` | 절차 · 신청 방법 · 따라 하기 · 단계별 추진 · 향후 계획 | 3~4단계, 단계마다 이름 + 할 일 3줄 이하 | 5단계부터 두 장 | `.road` |
| 관계 | 둘 비교 | `compare` | 문제점 ↔ 개선 방안, 문단 ↔ 고른 장표, 기존안 ↔ 새 안 | 2~3줄, 줄마다 왼쪽 · 오른쪽 한 짝 | 4줄부터 두 장 | `.fix (+ .stack)` — 누를 때마다 한 줄씩 보이려면 data-step |
| 관계 | 전→후 | `before-after` | 현행 → 개선, 사업 전 → 사업 후(숫자가 있는 짝) | 2~3짝, 같은 기준 · 같은 단위 | 가장 큰 변화 3짝만 | `.ba (+ .ba-head)` |
| 관계 | 묶음·분류 | `groups` | 과제 · 프로그램을 갈래로 나눈 것 | 2~4묶음, 묶음마다 3줄 이하 | 묶음마다 한 장 | `.card + .grid.g2/.g3/.g4` |
| 관계 | 체계 | `tree` | 비전 → 전략 → 과제, 추진 체계, 조직도 | 맨 위 1 + 갈래 2~4 + 갈래마다 2~3줄 | 갈래마다 한 장, 또는 표로 | `.tree` — 갈래 수는 style="--n:3" |
| 수 | 큰 숫자 | `numbers` | 핵심 실적 · 규모 · 예산 총액 | 1~4개, 숫자마다 단위 + 한 줄 | 가장 중요한 3개만 | `.tile (+ .delta)` |
| 수 | 막대 비교 | `bars` | 항목 간 크기 비교 · 순위 · 목표 대비 실적 | 3~5줄, 한 가지 단위 | 위 4개 + 나머지 합 | `.goal + .g-row` — 목표선이 없으면 .bars + .bar |
| 수 | 추이 | `trend` | 여러 해 · 여러 달에 걸친 변화 | 3~8시점, 한 가지 값 | 시점을 줄인다 | `.trend` — 가장 큰 값 = --v:100 |
| 수 | 구성비 | `share` | 전체 중 몫 · 재원 비율 | 2~5조각, 합 100% | 작은 조각은 기타로 | `.share + .sh-bar` — 설문 다섯 단계 응답은 .likert |
| 수 | 표 | `table` | 표로 된 지원 내용 · 항목 목록 · 예산 내역 | 3~5행 × 3~4열, 칸마다 1줄 | 6행부터 두 장, 또는 핵심 열만 | `.tbl` |
| 시간 | 일정 | `timeline` | 추진 일정 · 연혁 · 과정 지도 | 이정표 3~5개(.mile) 또는 줄 3~5개 × 12달(.gantt) | 분기 · 학기로 묶는다 | `.mile` — 달 단위 기간이 겹치면 .gantt |
| 그림 | 사진+글 | `photo` | 사례 · 현장 사진 · 활동 모습 | 사진 1~3장, 사진마다 제목 + 한 줄 + 말 한마디 | 사진마다 한 장 | `.case + .ph` — 사진은 사용자에게 받는다. 없으면 .ph data-need 로 자리만 |
| 그림 | 화면 짚기 | `screen` | 프로그램 화면 · 서식 · 누리집 사용법 | 캡처 1장 + 번호 표시 3개 이하 | 동작 하나에 한 장 | `.shot + .shot-img` — 번호 자리는 style="--x:%;--y:%" |
| 청중에게 | 질문 | `ask` | 여는 질문 · 토의 주제 · 퀴즈 · 자주 묻는 질문 | 질문 1개 + 보기 4개 이하(ol) 또는 답 1개(.a-a) | 질문마다 한 장 | `.ask` — 퀴즈 답은 .a-a 에 data-step="1" 을 붙여 가렸다 연다. 이 장은 .title 없이 |
| 청중에게 | 할 일 | `todo` | 실습 안내 · 과제 · 제출 서류 · 신청 기한 | 할 일 한 문장 + 조건 칸 2~3개(시간 · 결과물 · 도움) | 할 일마다 한 장 | `.todo` — 이 장은 .title 없이 |

23개 모두 덱 키트에 부품이 있고, 여덟 계열 예시 덱에 한 번 이상 쓰였다.

### 고를 때의 순서

한 문단이 둘 이상에 맞으면 위에서부터 먼저 맞는 것을 고른다.

1. 숫자가 주인공이면 수 묶음에서 고른다(하나면 큰 숫자, 시간 축이 있으면 추이, 합이 100%면 구성비, 나머지는 막대 비교).
2. 날짜가 주인공이면 일정.
3. 두 쪽이 맞서면 둘 비교, 같은 것이 달라졌으면 전→후.
4. 차례가 있으면 순서·단계, 위아래가 있으면 체계, 갈래만 있으면 묶음·분류.
5. 칸이 3열 이상 필요하면 표.
6. 어디에도 안 맞으면 항목. 항목이 한 개면 한 문장.

### 모든 본문 장에 공통인 것

- 무대는 1920 × 1080, 읽는 글 28px 이상 · 보조 글 22px 이상, 머리말과 제목 아래 본문 높이는 600~680px.
- **한 장에 기본 장표 하나.** 도식 두 개가 필요하면 두 장으로 나눈다.
- 장마다 머리말(어느 자리인지) + 결론 한 문장 제목 + 부품. 한 문장 · 질문 · 할 일 장만 제목 없이 머리말 아래에 부품을 둔다. 수치가 있으면 출처.
- 강조색은 한 장에 한 곳.

## 4. 흐름

흐름은 기본 장표에 자리 이름을 붙여 순서대로 엮은 것이다. 장 수는 내용이 정하고, 해당 내용이 문서에 없으면 그 자리는 건너뛴다.

### 계획안 발표

계획안 문서의 내용을 발표로 옮길 때. 예시 덱 원본 `src/flows/plan.html`.

| 자리 | 기본 장표 |
|---|---|
| 여는 장 | 표지 · 목차 |
| 추진 배경 | 한 문장 · 큰 숫자 · 막대 비교 · 추이 |
| 목표 · 추진 체계 | 한 문장 · 체계 |
| 세부 추진 과제 | 묶음·분류 · 항목 · 둘 비교 · 순서·단계 |
| 추진 일정 | 일정 |
| 예산 | 표 · 구성비 |
| 기대 효과 | 전→후 · 항목 |
| 맺는 장 | 맺음 |

### 성과 공유회

한 해 사업의 결과를 알릴 때. 예시 덱 원본 `src/flows/share.html`.

| 자리 | 기본 장표 |
|---|---|
| 여는 장 | 표지 · 목차 |
| 사업 개요 | 항목 |
| 추진 경과 | 일정 |
| 핵심 성과 | 큰 숫자 · 막대 비교 · 추이 · 구성비 |
| 우수 사례 | 사진+글 · 인용 |
| 변화 · 만족도 | 전→후 · 구성비 |
| 시사점 | 둘 비교 |
| 향후 계획 | 순서·단계 |
| 맺는 장 | 맺음 |

### 사업 설명회

지원 사업을 안내하고 신청을 받을 때. 예시 덱 원본 `src/flows/brief.html`.

| 자리 | 기본 장표 |
|---|---|
| 여는 장 | 표지 |
| 사업 소개 | 항목 |
| 지원 내용 | 표 |
| 신청 자격 · 절차 | 항목 · 순서·단계 |
| 주요 일정 | 일정 |
| 준비할 것 | 할 일 |
| 자주 묻는 질문 | 질문 |
| 맺는 장 | 맺음 |

### 연수 한 차시

교직원 연수 · 강의 한 차시. 예시 덱 원본 `src/flows/lecture.html` · `src/flows/lecture2.html` · `src/flows/lecture3.html`.

| 자리 | 기본 장표 |
|---|---|
| 열기 | 표지 · 일정 · 목차 · 항목 |
| 왜 배우나 | 질문 · 한 문장 |
| 설명 | 용어 정의 · 둘 비교 · 전→후 |
| 시연 | 화면 짚기 · 순서·단계 |
| 실습 | 할 일 |
| 확인 | 질문 |
| 닫기 | 인용 · 항목 · 할 일 · 맺음 |

여러 차시 과정이면 맨 앞에 **일정** 장표를 과정 지도로 쓴다(차시마다 이정표 하나, 지금 차시만 강조). 차시마다 연수 한 차시 흐름을 되풀이한다.

## 5. 옛 분류에서 옮기기

성과 공유회 정형 유형(`kind`)과 `info_type`은 아래처럼 기본 장표의 자리 이름이 된다. 새 장표에는 `pattern`(위 표의 id)을 적는다.

| 옛 `kind` | 기본 장표 |
|---|---|
| 사업 개요 | 항목 |
| 추진 체계 | 체계 |
| 추진 경과 | 일정 |
| 주요 추진 내용 | 묶음·분류 |
| 핵심 성과 | 큰 숫자 |
| 목표 대비 달성 · 전년 대비 · 비교 | 막대 비교 |
| 추이 | 추이 |
| 구성비 · 만족도 | 구성비 |
| 참여 분포 | 막대 비교(지역별) — 지도는 기본 장표가 아니다 |
| 우수 사례 | 사진+글 |
| 참여자 목소리 | 인용 |
| 전후 비교 | 전→후 |
| 시사점 · 과제 | 둘 비교 |
| 향후 계획 · 단계 · 절차 | 순서·단계 |
| 요약표 | 표 |
| 자주 묻는 질문 | 질문 |

## 6. 아직 없는 것

- 화면 짚기 · 사진+글의 실제 이미지(지금은 자리만 있다). 예시 덱에 넣을 화면 캡처 · 사진을 받으면 채운다.
- 계획안 발표 · 성과 공유회에서 연수 2 · 3차시처럼 한 흐름에 덱이 여럿인 경우는 `data/flows.json`의 `more`에 적는다.
