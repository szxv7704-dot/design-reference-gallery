# 기본 장표 틀

이 갤러리의 분류 기준이다. 장표를 "어떤 행사에 쓰나"가 아니라 **"내용이 어떤 모양인가"**로 나눈다.
기존 장표 판정은 [`triage.md`](triage.md), 그림 · 피할 것 같은 제작 규칙은 [`criteria.md`](criteria.md).

상태: **초안(검토 전)**. 내용 조건의 숫자는 키트의 높이 예산에서 어림한 제안값이고, 부품을 만들면서 실제로 재어 고친다.

## 1. 이 갤러리를 쓰는 방식

1. 사용자가 채팅 AI(Claude · ChatGPT)에게 **이 갤러리 주소와 자기 한글 문서**(계획안 · 연수 강의안 · 성과 보고 등)를 준다.
2. AI는 문서를 읽고, 여기 있는 디자인을 참고 · 재료로 삼아 **16:9 발표 덱 HTML**을 만든다.

그래서 갤러리의 첫 번째 독자는 AI다. 여기서 세 가지가 따라 나온다.

- 분류는 AI가 하는 일의 순서와 같아야 한다: 문단을 읽는다 → 그 문단의 모양을 정한다 → 그 모양의 장표를 고른다.
- AI가 읽는 면은 스크립트 없이 글로 읽혀야 하고, 한 장만 읽어도 덱을 만들 수 있어야 한다.
- 자료는 두 가지로 나뉜다.
  - **재료**: AI가 그대로 가져다 조립하는 코드. 한 벌의 규격(덱 키트)으로 만든 부품만 해당한다.
  - **참고**: "이렇게도 풀 수 있다"는 생각거리. 기존 레퍼런스 장표가 여기에 해당한다. 썸네일과 요점만 넘기고 코드는 넘기지 않는다.

## 2. 세 층

| 층 | 무엇 | 정하는 것 |
|---|---|---|
| 1. 기본 장표 | 내용의 모양 23가지 | 한 장의 짜임 |
| 2. 흐름 | 기본 장표를 순서대로 엮은 것(계획안 발표 · 성과 공유회 · 설명회 · 연수 한 차시) | 덱의 순서 |
| 3. 분위기 | 색 · 글꼴 · 상징 부품(A~D 키트) | 덱의 겉모습 |

세 층은 서로 독립이다. 어떤 흐름이든 어떤 분위기로든 나와야 하고, 기본 장표는 모든 분위기에 다 있어야 한다.
행사마다 새 장표 유형을 만들지 않는다. 행사에 따라 달라지는 것은 순서와 자리 이름뿐이다.

## 3. 기본 장표 23가지

`재료` 열은 지금 덱 키트에 그 부품이 있는지다(● 있음 · ◐ 다른 용도 부품으로 대신 · ○ 없음).

### 뼈대

| 기본 장표 | `pattern` | 문서에서 이런 내용이면 | 내용 조건 | 넘치면 | 재료 |
|---|---|---|---|---|---|
| 표지 | `cover` | 문서 제목 · 기관 · 날짜 | 제목 2줄 이하, 부제 1줄 | 부제를 뺀다 | ● `.cover` |
| 목차 | `toc` | 문서의 큰 번호(Ⅰ · Ⅱ · Ⅲ) | 3~6줄 | 큰 묶음으로 합친다 | ● `.toc` |
| 간지 | `divider` | 큰 번호가 바뀌는 자리 | 번호 + 이름 한 줄 | — | ● `.divider` |
| 맺음 | `closing` | 문의처 · 담당 · 자료 위치 | 한 문장 + 연락처 3줄 이하 | — | ● `.close` |

### 글

| 기본 장표 | `pattern` | 문서에서 이런 내용이면 | 내용 조건 | 넘치면 | 재료 |
|---|---|---|---|---|---|
| 한 문장 | `statement` | 목적 · 비전 · 결론처럼 한 문장이 전부인 곳 | 40자 이하 한 문장 + 받치는 말 1줄 | 받치는 말을 다음 장으로 | ○ |
| 항목 | `points` | 개조식(□ · ○ · -) 항목 3~5개 | 3~5개, 항목마다 이름 + 1~2줄 | 6개부터 두 장, 또는 묶음 · 분류로 | ◐ `.card` · `.brief` |
| 용어 정의 | `define` | "○○란", 용어 풀이, 개념 설명 | 용어 1개 + 뜻 한 문장 + 예 1~2개 | 용어마다 한 장 | ○ |
| 인용 | `quote` | 참여자 말 · 설문 서술 답 · 법령 조문 | 1~3개, 각 60자 이하, 말한 사람 | 가장 강한 것 하나만 | ◐ `.case` 안에서만 |

### 관계

| 기본 장표 | `pattern` | 문서에서 이런 내용이면 | 내용 조건 | 넘치면 | 재료 |
|---|---|---|---|---|---|
| 순서 · 단계 | `steps` | 절차 · 신청 방법 · 따라 하기 · 단계별 추진 | 3~6단계, 단계마다 이름 + 할 일 2줄 | 7단계부터 두 장 | ● `.road` |
| 둘 비교 | `compare` | 문제점 ↔ 개선 방안, 맞는 예 ↔ 아닌 예, 기존안 ↔ 새 안 | 2열, 2~4줄, 줄마다 짝 | 5줄부터 두 장 | ● `.fix` |
| 전 → 후 | `before-after` | 현행 → 개선, 사업 전 → 사업 후, 고치기 전 → 고친 뒤 | 2~4짝, 같은 기준으로 | 가장 큰 변화 3짝만 | ● `.ba` |
| 묶음 · 분류 | `groups` | 과제 · 프로그램을 갈래로 나눈 것 | 2~4묶음, 묶음마다 3~4개 | 묶음마다 한 장 | ● `.card` + `.grid` |
| 체계 | `tree` | 비전 → 목표 → 과제, 추진 체계, 조직도 | 3층 이하, 맨 아래층 6칸 이하 | 층마다 한 장, 또는 표로 | ○ |

### 수

| 기본 장표 | `pattern` | 문서에서 이런 내용이면 | 내용 조건 | 넘치면 | 재료 |
|---|---|---|---|---|---|
| 큰 숫자 | `numbers` | 핵심 실적 · 규모 · 예산 총액 | 1~4개, 숫자마다 단위 + 한 줄 | 가장 중요한 3개만 | ● `.tile` · `.delta` |
| 막대 비교 | `bars` | 항목 간 크기 비교 · 순위 · 목표 대비 실적 | 3~8줄, 한 가지 단위 | 위 5개 + 나머지 합 | ● `.bars` · `.goal` |
| 추이 | `trend` | 여러 해 · 여러 달에 걸친 변화 | 3~8시점, 선 1~2개 | 시점을 줄이거나 선마다 한 장 | ○ |
| 구성비 | `share` | 전체 중 몫 · 재원 비율 · 설문 응답 분포 | 2~5조각, 합 100% | 작은 조각은 '기타'로 | ◐ `.likert`(설문 전용) |
| 표 | `table` | 표로 된 지원 내용 · 항목 목록 · 예산 내역 | 3~6행 × 3~5열, 칸마다 1줄 | 7행부터 두 장, 또는 핵심 열만 | ● `.tbl` |

### 시간

| 기본 장표 | `pattern` | 문서에서 이런 내용이면 | 내용 조건 | 넘치면 | 재료 |
|---|---|---|---|---|---|
| 일정 | `timeline` | 추진 일정 · 연혁 · 차시 시간표 | 이정표 3~6개, 또는 줄 3~6개 × 12칸 | 분기 · 학기로 묶는다 | ● `.mile` · `.gantt` |

### 그림

| 기본 장표 | `pattern` | 문서에서 이런 내용이면 | 내용 조건 | 넘치면 | 재료 |
|---|---|---|---|---|---|
| 사진 + 글 | `photo` | 사례 · 현장 사진 · 활동 모습 | 사진 1장 + 제목 + 2~3줄 | 사진마다 한 장 | ● `.case` · `.ph` |
| 화면 짚기 | `screen` | 프로그램 화면 · 서식 · 누리집 사용법 | 캡처 1장 + 번호 표시 3개 이하 | 동작 하나에 한 장 | ○ |

### 청중에게

| 기본 장표 | `pattern` | 문서에서 이런 내용이면 | 내용 조건 | 넘치면 | 재료 |
|---|---|---|---|---|---|
| 질문 | `ask` | 여는 질문 · 토의 주제 · 퀴즈(답을 가렸다 연다) · 자주 묻는 질문 | 질문 1개 + 보기 4개 이하 또는 답 1개 | 질문마다 한 장 | ○ |
| 할 일 | `todo` | 실습 안내 · 과제 · 제출 서류 · 신청 기한 | 할 일 1개 + 시간 · 결과물 · 도움 받을 곳 | 할 일마다 한 장 | ○ |

**재료 현황**: 23개 중 있음 13 · 대신 쓰는 것 3 · 없음 7(한 문장 · 용어 정의 · 체계 · 추이 · 화면 짚기 · 질문 · 할 일).

### 고를 때의 순서

한 문단이 둘 이상에 맞으면 위에서부터 먼저 맞는 것을 고른다.

1. 숫자가 주인공이면 수 묶음에서 고른다(하나면 큰 숫자, 시간 축이 있으면 추이, 합이 100%면 구성비, 나머지는 막대 비교).
2. 날짜가 주인공이면 일정.
3. 두 쪽이 맞서면 둘 비교, 같은 것이 달라졌으면 전 → 후.
4. 차례가 있으면 순서 · 단계, 위아래가 있으면 체계, 갈래만 있으면 묶음 · 분류.
5. 칸이 3열 이상 필요하면 표.
6. 어디에도 안 맞으면 항목. 항목이 한 개면 한 문장.

### 모든 본문 장에 공통인 것

- 무대는 1920 × 1080, 읽는 글 28px 이상 · 보조 글 22px 이상, 머리말과 제목 아래 본문 높이는 600~680px(키트 지시서 기준).
- **한 장에 기본 장표 하나.** 도식 두 개가 필요하면 두 장으로 나눈다.
- 장마다 머리말(어느 자리인지) + 제목 + 본문. 수치가 있으면 출처.
- 강조색은 한 장에 한 곳.

## 4. 흐름

흐름은 기본 장표에 자리 이름을 붙여 순서대로 엮은 것이다. 장 수는 내용이 정하고, 해당 내용이 문서에 없으면 그 자리는 건너뛴다.

### 계획안 발표

| 자리 | 기본 장표 |
|---|---|
| 여는 장 | 표지 → 목차 |
| 추진 배경 | 한 문장 · 큰 숫자 · 막대 비교 |
| 목표 · 추진 체계 | 한 문장 → 체계 |
| 세부 추진 과제 | 묶음 · 분류 → (과제마다) 항목 · 둘 비교 · 순서 · 단계 |
| 추진 일정 | 일정 |
| 예산 | 표 · 구성비 |
| 기대 효과 | 전 → 후 · 항목 |
| 맺는 장 | 맺음 |

### 성과 공유회

| 자리 | 기본 장표 |
|---|---|
| 여는 장 | 표지 → 목차 |
| 사업 개요 | 항목(목적 · 대상 · 기간 · 규모) |
| 추진 경과 | 일정 |
| 핵심 성과 | 큰 숫자 → 막대 비교 · 추이 · 구성비 |
| 우수 사례 | 사진 + 글 · 인용 |
| 변화 · 만족도 | 전 → 후 · 구성비 |
| 시사점 | 둘 비교 |
| 향후 계획 | 순서 · 단계 |
| 맺는 장 | 맺음 |

### 사업 설명회

| 자리 | 기본 장표 |
|---|---|
| 여는 장 | 표지 |
| 사업 소개 | 항목 |
| 지원 내용 | 표 |
| 신청 자격 · 절차 | 항목 → 순서 · 단계 |
| 주요 일정 | 일정 |
| 준비할 것 | 할 일 |
| 자주 묻는 질문 | 질문 |
| 맺는 장 | 맺음 |

### 연수 한 차시

| 자리 | 기본 장표 |
|---|---|
| 열기 | 표지(차시 제목) → 항목(학습 목표) → 일정(차시 순서) |
| (2차시부터) 되짚기 | 항목(지난 차시 세 줄) |
| 왜 배우나 | 질문 · 한 문장 |
| 설명 | 용어 정의 → 둘 비교(맞는 예 ↔ 아닌 예) · 전 → 후(고치기 전 → 뒤) |
| 시연 | 화면 짚기 → 순서 · 단계 |
| 실습 | 할 일 |
| 확인 | 질문(퀴즈, 답 가렸다 열기) |
| 닫기 | 항목(핵심 정리) → 할 일(과제) → 맺음(또는 다음 차시 예고) |

여러 차시 과정이면 맨 앞에 **목차** 장표를 과정 지도로 쓴다(차시 한 줄씩, 지금 차시만 강조). 차시마다 위 흐름을 되풀이한다.

## 5. 옛 분류에서 옮기기

성과 공유회 정형 유형(`kind`, criteria.md 3)은 아래처럼 기본 장표의 자리 이름이 된다. 새 장표에는 `pattern`을 적는다.

| 옛 `kind` | 기본 장표 |
|---|---|
| 사업 개요 | 항목 |
| 추진 체계 | 체계 |
| 추진 경과 | 일정 |
| 주요 추진 내용 | 묶음 · 분류 |
| 핵심 성과 | 큰 숫자 |
| 목표 대비 달성 · 전년 대비 · 비교 | 막대 비교 |
| 추이 | 추이 |
| 구성비 · 만족도 | 구성비 |
| 참여 분포 | 막대 비교(지역별) — 지도는 기본 장표가 아니다 |
| 우수 사례 | 사진 + 글 |
| 참여자 목소리 | 인용 |
| 전후 비교 | 전 → 후 |
| 시사점 · 과제 | 둘 비교 |
| 향후 계획 · 단계 · 절차 | 순서 · 단계 |
| 요약표 | 표 |
| 자주 묻는 질문 | 질문 |

## 6. 이 틀과 어긋나 있어 정해야 할 것

- **criteria.md 1**은 "계획안은 이 갤러리의 대상이 아니다"라고 적고 있다. 계획안 내용을 발표 덱으로 만드는 것도 쓰임새에 들어가므로, "결재용 계획안 문서를 만들지 않는다 · 계획안의 내용을 발표 덱으로 옮기는 것은 대상이다"로 고쳐야 한다.
- **criteria.md 8**(루틴 규칙)은 `kind` 19가지 중 하나를 고르라고 한다. 틀이 확정되면 `pattern` 23가지와 "한 장에 기본 장표 하나"로 바꾼다.
- **첫 화면**(`index.html`)의 '무엇을 보여 주나' 칩과 `scripts/gaps.py`는 `kind` 기준이다. 틀이 확정되면 `pattern` 기준으로 바꾼다.
