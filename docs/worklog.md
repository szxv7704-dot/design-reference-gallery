# 작업 기록

갤러리를 "사람이 스타일을 고르고, AI가 그 스타일을 실제 발표에 적용하는 곳"으로 만드는 작업의 기록이다.
**다음 실행은 맨 아래 '다음 시작점'부터 이어 간다.** 현황 파악을 처음부터 다시 하지 않는다.

## 완료 기준

- 사람이 스타일의 차이와 용도를 이해하고 고를 수 있다.
- 표지부터 마무리까지 하나의 발표처럼 보인다.
- AI가 설명과 코드를 읽고 디자인의 핵심 특징을 재현할 수 있다.
- 다른 발표 내용에도 쓸 수 있다.
- 내려받은 발표가 실제로 열리고 넘어간다.

세트 하나가 갖출 열 가지 역할(`data/roles.json`): 표지 · 목차/흐름 · 핵심 개념 · 비교 · 순서/절차 · 사례/화면 · 실습/행동 안내 · 핵심 수치 · 요약 · 마무리.

## 상태 구분

| 상태 | 뜻 |
|---|---|
| 검증된 세트 | 10장 예시 + 다른 주제 시험 + 넘침 검사 + 내려받기 확인을 통과했고, 본문이 스타일의 특징을 이어받는다 |
| 확장 중 | 10장 예시는 있으나 본문이 색 · 글꼴 위주이거나 검증이 남았다 |
| 표지만 있음 | 표지만 있고 그 특징을 이어받은 본문이 없다 |

## 2026-11-13 최초 실행에서 한 것

1. **현황 파악**: 표지 27개에 이어지는 본문은 "색 · 글꼴만 입힌 공용 본문 12장"뿐이었다. 개념 · 사례 · 실습 · 요약 구성은 예시가 없었다(부품만 있었다).
2. **10장 세트 예시**: 열 가지 역할을 한 장씩 담은 예시 발표(`src/flows/set.html`, 가상 주제: 생성형 AI 업무 활용 연수)를 여덟 스타일로 빌드. `kit/{ID}-set.html`
3. **다른 주제 시험**: 성격이 다른 본문 다섯 장(`src/flows/set2.html`, 가상 주제: 학교 독서 활동 — 묶음 · 추이 · 인용 · 일정 · 질문). `kit/{ID}-set2.html`
4. **화면 개편**: 메뉴(전체 스타일 · 본문 구성 · 모션·강조 · 인쇄·홍보물 · 이용 방법), 스타일 카드(표지 + 본문 3장 + 상태), 분위기 필터 · 검색 · 완성된 세트만 · 비교, 스타일 화면(10장 미리보기 · 구성별 쓰는 법 · 내려받기 · 요청문), AI 요청문 두 가지(선택 맡기기 / 고른 스타일 적용). `scripts/gallery.py`
5. **AI용 목록**: `catalog.md`에 적용 순서 여섯 단계 · 스타일 표(ID · 상태 · 주소) · 구성 표(분량 · 넘칠 때 · 다른 구성)를 넣었다. 스타일별 적용 안내는 `kit/{ID}.md`.
6. **정리**: 옛 첫 화면은 '참고 장표 모음'(`refs.html`)으로 옮겼다. 인쇄 · 홍보물과 특수 발표 틀은 `print.html`로 분리.

### 실제로 한 검증

- 여덟 스타일 × 10장, 여덟 스타일 × 다른 주제 5장을 브라우저로 그려 한 장씩 눈으로 확인.
- `node scripts/check.js kit {ID}-set {ID}-set2`: 16개 모두 통과(1920 × 1080 밖 넘침 없음 · 22px 미만 글자 없음 · 바깥 요청 없음 = 인터넷 없이 열림).
- 새 화면: 스크립트 오류 없음, 390px 폭에서 가로 넘침 없음, 필터 · 비교 · 스타일 화면 이동 확인.
- 표지별 미리보기(`deck.html`): `node scripts/check_decks.js` 363장 중 본문 324장 문제 없음. 표지 7장은 그림이 무대 밖으로 걸치는 연출이거나 픽셀 고정 크기라 걸림(화면으로 확인, 보기에는 이상 없음).

### 하지 못한 검증

- **실제 Claude · ChatGPT에 주소와 요청문을 줘서 적용시켜 보는 시험.** 이 작업 환경에서는 공개 주소에 접속할 수 없다. 사용자가 해 보고 결과를 알려 줘야 한다.
- 긴 한국어 제목(두 줄 넘는 경우) · 항목 수를 최대로 채운 경우의 배치는 예시 내용으로만 봤다.
- 강당 화면 · 밝은 회의실에서의 실제 가독성.

## 2026-11-13 두 번째 실행: 구성이 달라야 한다

사용자 지적: "디자인만 다르고 구성이 똑같으면 여러 개가 있을 이유가 없다. 목차 · 개념 · 비교 · 절차를 **다른 방식으로** 보여 주는 덱이 있어야 한다." 휴대폰에서 메뉴가 화면 절반을 가린다는 것도.

1. **역할마다 배치가 다른 구성 셋**(8역할 × 3 = 24): 정의 `data/variants.json`, 코드 `src/flows/var.html`, 새 부품 7종은 `kit/parts.css`(번호 카드 `.agenda` · 맞는 예/아닌 예 `.yesno` · 기준별 두 열 `.vs` · 세로 단계 `.stepper` · 한 건 이야기 `.story` · 체크 목록 `.check` · 숫자 하나 크게 `.big`). 나머지는 이미 있던 부품을 다른 역할에 썼다.
2. **스타일마다 10장 예시의 조합이 다르다**(`variants.json`의 `picks`). `src/flows/set.html`은 없앴고 `kit.py`가 구성 모음에서 골라 짠다. 구성 모음 전체는 `kit/{ID}-var.html`(26장).
3. **본문 구성 화면**(`body.html`): 같은 구성 × 여덟 스킨이 아니라, 역할마다 구성 셋을 나란히. 위의 '입혀 볼 스타일'로 스킨만 바꿔 본다. 스타일 화면에는 '다른 구성으로 바꾸기'(그 스타일로 그린 24구성, 예시에 쓴 것 표시).
4. **AI용**: `catalog.md` 구성 표가 24구성 + 스타일별 조합 표로, `kit/{ID}.md`에 역할별 구성 표와 모든 구성의 코드. 요청문에 "예시의 조합을 따라 하지 말고 내용에 맞는 구성을 고르라"를 넣었다.
5. **휴대폰 메뉴**: 820px 아래에서는 한 줄로 가로로 밀고, 화면을 따라다니지 않는다.

검증: 여덟 스타일 × 구성 모음 26장과 10장 예시를 브라우저로 그려 모아 보고 확인(처음에 '기준별 두 열' · '맞는 예/아닌 예'가 작고 휑해 키웠고, 10장 예시가 앞 장까지 딸려 오는 빌드 버그를 고쳤다). `node scripts/check.js kit {ID}-set {ID}-var` 16개 모두 통과(넘침 · 22px 미만 글자 · 바깥 요청 없음). 화면은 390px 폭에서 가로 넘침 없음, 스타일 바꾸기 동작 확인. **공개 주소와 실제 AI 적용 시험은 이번에도 하지 못했다.**

남은 한계: 구성 24개 중 새로 만든 것은 7개이고, 스타일 고유의 문법(픽셀 창 · 이중 괘선 등)이 구성 자체를 바꾸지는 않는다(같은 구성은 어느 스타일에서나 같은 배치다). 스타일마다 **조합**이 다를 뿐이다.
