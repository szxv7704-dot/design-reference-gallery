픽셀 작업실

코드 편집기 화면이 곧 포스터. ▶ 실행을 누르면 명령이 한 글자씩 쳐지고 결과가 찍힌다. "코드는 어렵다"를 "실행하면 결과가 나온다"로 바꿔 보여 주는 연수 홍보물.

원본 그림의 편집기·파일 트리·변수 창은 그대로 두고, 실행 결과와 터미널 줄을 지운 뒤 살아 있는 글자로 다시 찍게 했다. 화면에 들어오면 한 번 저절로 실행되고, ▶ 실행으로 다시 볼 수 있다. 틀려 있던 줄 번호도 고쳤다. 가상 예시

01고친 곳

줄 번호 바로잡기

22·23·24·25 다음에 24·25·26이 다시 나왔다. 26·27·28로 고쳤다. 코드 화면은 개발자가 보면 바로 티가 나는 곳이라, 줄 번호·괄호·들여쓰기는 꼭 검산할 것.

결과는 살아 있는 글자로

실행 결과 4줄과 터미널 3줄을 그림에서 지우고 같은 자리·같은 크기의 고정폭 글자로 다시 얹었다. 그래서 타자 치듯 찍히는 연출이 가능하고, 문구도 바꿀 수 있다.

손대지 않은 것코드 본문, 저장된 목록(JSON) 미리보기, 프로젝트 파일 트리, 변수 확인 칸은 원본 그대로다. 코드 내용도 실제로 돌아가는 파이썬이다(assets 폴더의 .txt 목록을 build/manifest.json으로 저장).

02가져갈 장치

01

실행 = 결과가 나오는 순간

명령을 한 글자씩 치고 결과 줄을 0.16초 간격으로 찍는다. 보는 사람이 "돌아간다"를 직접 본다.

자동화 연수 홍보, 도구 시연 화면, 발표 첫 장

02

한 화면에 원인 → 결과

왼쪽 코드(원인) → 오른쪽 결과·파일 트리·변수(결과). 설명 없이 인과가 읽힌다.

업무 개선 전후 비교, 절차 안내

03

어두운 화면 + 4색 문법 강조

남색 바탕 위 하늘·초록·분홍·노랑. 색마다 역할(명령·성공·키워드·숫자)이 하나씩.

04인쇄 전에

  • 인쇄하면 실행 연출 대신 마지막 화면이 찍힌다(결과가 모두 보이는 상태).
  • 어두운 바탕 대면적 인쇄는 잉크가 많이 든다 — 리치 블랙 대신 C80 M60 Y40 K80 정도의 남색 지정, 교정쇄 필수.
  • 작은 고정폭 글자(파일 트리)는 A3 가로에서 약 7pt. A4로 줄이면 읽기 어렵다.

06HTML 코드

  1. 코드를 빈 .html 파일로 저장하면 포스터 한 장이 그대로 열립니다(바탕 그림·글꼴 포함, 인터넷 연결 없이도).
  2. 문구는 마크업의 글자를, 위치·크기는 u 단위(지면 폭 기준) 숫자를 바꾸면 됩니다.
  3. 인쇄: 크롬에서 열고 인쇄 → PDF로 저장, 여백 없음, 배경 그래픽 켜기.
  4. AI 채팅에는 링크 대신 이 코드를 붙여 넣으세요.
